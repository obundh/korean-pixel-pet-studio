# PixelPet Studio v0.2.0

v0.2.0은 4칸 포즈 시트를 실제 펫 프레임으로 정리하고 재생까지 검증하는 흐름을 다듬으면서, 오픈소스 배포와 권리 안내도 전면 정비한 릴리스입니다.

## 주요 변경

- 가로로 배치된 4칸 포즈 시트를 왼쪽부터 `0, 1, 2, 3` 프레임으로 가져올 수 있습니다.
- **이 동작 한 번에 정리**에서 배경 제거, 공통 정렬, `64×64` 캔버스 배치와 내보내기 준비를 함께 처리합니다.
- 단색 크로마 배경은 로컬 AI 모델을 거치지 않고 색상 거리·despill·HSV와 색 방향 검사로 바로 정리합니다. 투명 배경에 연결된 잔색만 가까운 정상 캐릭터 색으로 복원해, 캐릭터 내부의 비슷한 색은 보존합니다.
- 네 프레임의 불투명 영역을 하나로 합친 공통 경계를 사용하므로 프레임마다 몸 크기가 달라지거나 기준선이 흔들리는 현상을 줄였습니다.
- 품질 검사와 실제 Electron 펫 창 재생 검사를 추가했습니다. 마지막 프레임에서 첫 프레임으로 돌아가는 구간도 검사합니다.
- 한 장짜리 **빠른 만들기**는 원본 비트맵을 늘이거나 찌그러뜨리지 않고 `0px → 위로 1px → 위로 1px → 0px`만 이동하는 간단한 확인 모드로 바꿨습니다.
- 결합된 데스크톱 앱 전체를 `AGPL-3.0-or-later`로 명확히 공개합니다.
- 공개 예시·레퍼런스 이미지에는 프로젝트가 실제로 허락할 수 있는 권리 범위에서 `CC BY 4.0` 자산 정책을 적용합니다. 저작권 성립, 독점성, 비침해 또는 제3자 권리 정리를 보증하는 표시는 아닙니다.
- 앱 상단의 **오픈소스** 버튼에서 저작권, 무보증, 재배포 조건, 소스 저장소와 설치 파일의 `legal` 폴더를 확인할 수 있습니다.
- 모든 데스크톱 패키지에 다음 자료를 포함합니다.
  - 정확한 Git commit과 소스 archive를 가리키는 `SOURCE_OFFER.txt`
  - `BUILD_PROVENANCE.json`
  - SPDX 2.3 런타임 SBOM
  - IMG.LY, ONNX Runtime, Electron/Chromium과 npm 런타임 의존성의 라이선스·고지
  - IS-Net 모델과 WASM 청크의 SHA-256 manifest
- 수정 파일이 남아 있는 개발 빌드는 공개 배포용 패키징을 거부합니다.
- 기존 v0.1.0 파일 이름을 덮어쓰지 않도록 앱 버전을 0.2.0으로 올렸습니다.

## 공개 샘플 재제작·검증

해오리, 몽글이, 토토 공개 샘플은 각각 생성형 AI로 만든 `ai-idle-sheet-chroma.png`를 앱의 **포즈 시트 한 장 가져오기 → 이 동작 한 번에 정리** 경로로 처리했습니다. 토토 시트는 실제 반복 재생에서 발견한 마지막 경계의 스냅을 없애기 위해 4번 칸을 시작 자세와 같은 실루엣으로 되돌리고 눈 반짝임만 남기는 최소 입력 보정을 추가했으며, 정확한 내용은 샘플의 `PROMPTS.md`에 기록했습니다. 세 시트는 모두 `2172×724`이며, 앱이 이를 가로로 똑같이 나눠 `543×724` 크기의 네 포즈로 읽었습니다. 공개 샘플 제작에는 빠른 만들기를 사용하지 않았습니다.

초보자도 결과를 확인할 수 있도록 각 샘플의 `run-log.json`에 다음 증거를 남겼습니다.

- 최종 프레임은 모두 `64×64`, 재생 속도는 `4 FPS`입니다.
- 반투명 경계 픽셀과 크로마색 테두리 픽셀은 모든 프레임에서 `0`으로 측정됐습니다.
- 네 프레임의 발밑 기준선은 모두 `y=58`로 같고, 캐릭터 전체를 눌러 찌그러뜨리거나 늘인 프레임이 없습니다.
- 실제 데스크톱 펫 창을 시간순으로 캡처해 예상 순서와 관찰 순서가 모두 `0 → 1 → 2 → 3 → 0`인지 확인했습니다.
- 측정된 프레임 간격은 모두 `4 FPS`의 목표 간격인 `250ms` 허용 범위이며, 샘플별 정확한 값은 각 `run-log.json`에 기록합니다.
- 입력·출력 파일 해시, 프레임별 품질 수치와 실제 재생 캡처 기록도 로그에 함께 저장했습니다.

이 검사는 “파일이 네 장 존재한다”는 것만 보는 검사가 아닙니다. 투명 배경이 딱딱하게 정리됐는지, 초록 테두리가 남지 않았는지, 발이 튀지 않는지, 마지막 장 다음에 실제로 첫 장이 나오는지까지 확인합니다.

## 빠른 만들기의 범위

빠른 만들기는 정지 이미지 한 장으로 설치와 재생을 빠르게 시험하는 보조 경로입니다. `4 FPS`에서 원본 픽셀 크기를 그대로 유지한 채 위아래로 `1px`만 옮기므로 무왜곡 bob 효과는 만들 수 있지만, 눈·팔·꼬리처럼 부위가 실제로 움직이는 포즈 애니메이션은 만들지 않습니다. 공개 샘플과 같은 결과가 필요하면 네 포즈를 먼저 만든 뒤 포즈 시트 경로를 사용해야 합니다.

## 외부 마스코트 주의

비상업·공익 프로젝트라도 기관 마스코트와 로고를 자동으로 사용할 수 있는 것은 아닙니다. 원본을 생성형 AI에 업로드하고 픽셀화·애니메이션·재배포하려면 해당 권리자의 허락이나 적용 가능한 공공누리 조건을 먼저 확인해야 합니다.

RRA 파비는 확인 가능한 공공누리 표시나 별도 허락이 확보되지 않았으므로 v0.2.0 공개 샘플에 포함하지 않습니다. 저장소에는 권리 확인과 제작 절차를 설명하는 recipe만 유지합니다.

## 공개 전 체크

1. 모든 소스 변경을 commit하고 공개 저장소에 push합니다.
2. `npm run quality:frames`와 `npm run smoke:frame-playback`으로 샘플 품질과 실제 순환 재생을 확인합니다.
3. package version과 같은 `v0.2.0` tag를 해당 commit에 붙입니다.
4. tag 빌드 워크플로로 macOS·Windows 패키지를 새로 만듭니다.
5. `npm run legal:check -- --packaged`가 통과하는지 확인합니다.
6. 바이너리와 같은 릴리스 화면에서 정확한 commit의 소스 archive를 함께 제공합니다.

현재 작업 트리에서 만든 테스트용 `.app`, `.dmg`, `.zip`, `.exe`는 공개하지 않습니다. 설치 파일 안의 `SOURCE_OFFER.txt`가 `CLEAN SOURCE BUILD`와 정확한 `v0.2.0` tag를 표시하는 새 빌드만 배포합니다.
